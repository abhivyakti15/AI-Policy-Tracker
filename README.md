# AI-Policy-Tracker

A small pipeline + dashboard tracking AI-related policy activity across Indian
states: missions and roadmaps, task forces / centres of excellence, MoUs with
companies or universities, AI deployed in governance (health, agriculture,
policing, education), state budget lines for AI, and regulatory/ethics moves.


**Dataset:** [`data/ai_policy_india.csv`](data/ai_policy_india.csv)

**Dashboard:** <https://abhivyakti15.github.io/AI-Policy-Tracker/site/dashboard.html>

## How this was actually built


1. **Collect** — targeted web searches per state (news articles, government
  department pages, and a couple of policy-tracking sites), reading enough
  of each source to extract the facts, not just the headline.

2. **`newsapi_pipeline.py`** — a real, runnable NewsAPI-based fetcher that
  automates the same job going forward: query NewsAPI per state, filter to
  things that look like state AI-policy activity, cluster near-duplicate
  coverage of the same event, categorize, and write
  `data/ai_policy_india_auto.csv` in the identical schema. This is what a
  scheduled/production version of this project would run daily.
  - Needs a free key from <https://newsapi.org/register>.
  - `pip install -r requirements.txt`
  - `export NEWSAPI_KEY=your_key_here`
  - `python3 scripts/newsapi_pipeline.py --states Telangana Karnataka`
  - **Caveats, read before trusting the output:** NewsAPI's free tier only
    returns roughly the last month of articles (so it can't backfill older
    history like Tamil Nadu's 2020 policy), it won't see state-government
    press releases NewsAPI hasn't indexed, and without `--use-llm` the
    `summary` field is the source's own description text, not a paraphrase
    — review before merging into the main CSV. Full detail is in the
    script's own docstring.
  - This script's fetch/dedupe/categorize logic was tested against mocked
    NewsAPI-shaped responses (not a live call) because the sandbox this
    project was built in doesn't have network access to newsapi.org.

## Run it yourself

No dependencies beyond Python 3 (standard library only) and a browser.


```bash
# regenerate CSV from NewsAPI
python3 scripts/newsapi_pipeline.py


# regenerate site/data.js from the CSV (do this after any CSV edit)
python3 scripts/export_site_data.py


# preview the dashboard locally
cd site && python3 -m http.server 8080
# then open http://localhost:8080
```

## Dataset schema


| field | meaning |
|---|---|
| `id` | stable record id, e.g. `AIP-014` |
| `state` | canonical full state name (e.g. `Uttar Pradesh`, never `UP`) |
| `state_code` | 2-letter code used in the UI |
| `date` | ISO `YYYY-MM-DD`; see `date_precision` for how exact this really is |
| `date_precision` | `day` \| `month` \| `year` — whether the source gave a full date, only a month, or only a year (in the latter two cases the day/month is padded to the 1st, not guessed) |
| `headline` | short, our own wording, not copied from any source |
| `category` | one of 7 fixed categories, see `RATIONALE.md` |
| `summary` | one-line, paraphrased summary in our own words |
| `source_name` | outlet or publisher of the canonical source |
| `source_url` | link to that source |
| `entities` | companies / institutions / officials named in the record |
| `also_reported_by` | other outlets that covered the *same* event (dedup trail, not extra rows) |
| `notes` | caveats: approximate dates, secondary sourcing, non-binding MoUs, etc. |


## Known holes (see RATIONALE.md for the full list)


- 8 states covered, 6 in depth (Telangana, Karnataka, Tamil Nadu, Andhra
 Pradesh, Maharashtra, Uttar Pradesh) + 2 lighter (Kerala, Goa). 20+ states
 are not covered at all — this was a deliberate depth-over-breadth call
 given the time budget.
- No live/scheduled ingestion — this is a point-in-time snapshot as of
 August 2026.
- A few dates are month- or year-precision because the source didn't give an
 exact day; these are flagged via `date_precision`, not silently guessed.
- A couple of sources are secondary (a news aggregator citing another
 outlet) rather than primary; flagged in `notes`.
